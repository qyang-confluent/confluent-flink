# Private Flink Access to an AWS VPC-Peered Kafka Cluster

## Customer runbook

This runbook describes how to configure Confluent Cloud for Apache Flink to access a private Confluent Cloud Dedicated Kafka cluster using AWS VPC peering and an AWS PrivateLink Gateway.

The procedure assumes:

* The Kafka cluster is a Confluent Cloud Dedicated cluster.
* The Kafka cluster already has AWS VPC peering configured.
* Flink and Kafka are deployed in the same AWS region.
* The customer has access to an AWS VPC where the PrivateLink interface endpoint will be created.

For self-managed Kafka or Amazon MSK, this runbook does not provide a generic network route from Flink into the customer VPC. Use the appropriate supported external-service connectivity pattern instead.

## Architecture

```text
Customer VPC
    |
    | AWS interface VPC endpoint
    |
Confluent Cloud PrivateLink Gateway
    |
Confluent Cloud for Apache Flink
    |
    | Internal Confluent Cloud routing
    |
Dedicated Kafka cluster using AWS VPC peering
```

The PrivateLink Gateway provides private connectivity from the customer VPC to Flink. Flink-to-Kafka traffic is routed internally within Confluent Cloud. For Dedicated clusters, the gateway must be configured in the same region as the Kafka cluster, even when the Kafka cluster uses VPC peering.

See [Private Networking with Confluent Cloud for Apache Flink](https://docs.confluent.io/cloud/current/flink/concepts/flink-private-networking.html) for the connectivity model and supported networking options.

## Prerequisites

* Confluent Cloud access with one of the following roles: OrganizationAdmin, EnvironmentAdmin, or NetworkAdmin.
* A Confluent Cloud environment containing the Flink resources.
* A Confluent Cloud Dedicated Kafka cluster using AWS VPC peering.
* The AWS region and customer VPC ID.
* Private subnets in the customer VPC for the interface endpoint.
* Permission to create AWS VPC interface endpoints, security groups, Route 53 private hosted zones, and DNS records.
* Kafka RBAC/ACL permissions for the Flink service account.

Confirm that the Kafka VPC peering connection is operational before configuring the Flink gateway. The [AWS VPC Peering documentation](https://docs.confluent.io/cloud/current/networking/peering/aws-peering.html) covers the peering request, acceptance, route tables, CIDR requirements, and DNS considerations.

## Step 1: Create the PrivateLink Gateway

1. In Confluent Cloud, open the target environment.
2. Select Network management.
3. Under For serverless products, select Add gateway configuration.
4. Choose PrivateLink.
5. Select Create configuration for From your VPC or VNet to Confluent Cloud.
6. Enter a gateway name.
7. Select AWS as the cloud provider.
8. Select the AWS region used by the VPC-peered Kafka cluster.
9. Submit the configuration.
10. Copy the generated PrivateLink Service ID. It is required when creating the AWS VPC endpoint.

The current Confluent Cloud workflow is documented in [Enable Private Networking with Confluent Cloud for Apache Flink](https://docs.confluent.io/cloud/current/flink/operate-and-deploy/private-networking.html).

### Optional CLI example

```bash
confluent network gateway create <gateway-name> \\
  --cloud aws \\
  --region <aws-region> \\
  --type ingress-privatelink
```

## Step 2: Create the AWS interface VPC endpoint

In the AWS VPC console:

1. Verify that DNS resolution and DNS hostnames are enabled for the VPC.
2. Open VPC > Endpoints and select Create endpoint.
3. Select PrivateLink Ready partner services.
4. Enter the PrivateLink Service ID generated by Confluent Cloud.
5. Select Verify service.
6. Select the VPC that is connected to the Confluent Cloud Kafka network through VPC peering.
7. Select private subnets in the required Availability Zones.
8. Disable Enable DNS name.
9. Attach a security group to the endpoint network interfaces.
10. Create the endpoint and record its VPC endpoint ID and endpoint DNS name.

The endpoint security group should permit TCP traffic from the required customer source networks. Confluent documents TCP ports 443 and 9092 for the endpoint; port 80 is optional and can be used for an HTTP-to-HTTPS redirect.

### Optional AWS CLI example

```bash
aws ec2 create-vpc-endpoint \\
  --vpc-id <vpc-id> \\
  --service-name <privatelink-service-id> \\
  --subnet-ids <subnet-id-1> <subnet-id-2> \\
  --region <aws-region> \\
  --no-private-dns-enabled \\
  --vpc-endpoint-type Interface
```

Refer to [Use AWS PrivateLink for Serverless Products on Confluent Cloud](https://docs.confluent.io/cloud/current/networking/aws-platt.html) for the AWS endpoint configuration and security-group requirements.

## Step 3: Create the PrivateLink Access Point

In Confluent Cloud:

1. Open the PrivateLink Gateway.
2. Select Access points.
3. Select Create access point.
4. Enter the AWS VPC endpoint ID from Step 2.
5. Enter an access point name.
6. Create the access point.
7. Wait until the gateway and access point show READY.

The access point registers the AWS VPC endpoint with the Confluent Cloud gateway.

## Step 4: Configure private DNS

Confluent Cloud provides a DNS domain for the access point. Configure Route 53 so that Flink requests resolve to the AWS interface endpoint.

1. In Confluent Cloud, open the READY gateway and copy the DNS domain for the access point.
2. In Route 53, create a Private Hosted Zone using that domain.
3. Associate the hosted zone with the VPC containing the interface endpoint.
4. Create a wildcard CNAME record:

   * Record name: `*`
   * Record type: `CNAME`
   * Value: the fully qualified DNS name of the AWS VPC endpoint

Do not hardcode individual Kafka broker hostnames in Route 53. Confluent Cloud broker names returned through metadata are not static.

For additional DNS details, see the [AWS PrivateLink DNS configuration](https://docs.confluent.io/cloud/current/networking/aws-platt.html) section.

## Step 5: Use the private Flink endpoint

From a client running inside the customer VPC, list the available Flink endpoints:

```bash
confluent flink region use --cloud aws --region <aws-region>
confluent flink endpoint list
```

Select the private Flink endpoint in the Confluent Cloud Console or Confluent CLI. If a private gateway is configured, the Cloud Console can use the private endpoint automatically after the networking configuration is complete.

If the operator is outside the VPC, use a supported private-access pattern such as a client inside the VPC or a reverse proxy. The public Flink endpoint cannot be used to access private Kafka data.

## Step 6: Validate connectivity

Perform the following checks from a client inside the customer VPC:

* Confirm that the private Flink hostname resolves to the interface endpoint path.
* Confirm TCP connectivity to port 443.
* Confirm that the endpoint security group allows traffic from the client subnet or CIDR.
* Confirm that the gateway and access point are in the READY state.
* Confirm that the Kafka cluster and gateway are in the same AWS region.
* Confirm that the Flink service account has the required Kafka RBAC and ACL permissions.
* Submit a test Flink statement that reads from a permitted Kafka topic.

A successful private setup should allow Flink statements to read and write the VPC-peered private Kafka cluster without sending Kafka data over the public internet.

## Important distinction

The PrivateLink Gateway is used for private access to Flink APIs, SQL submission, statement management, and result retrieval. It does not create a second AWS VPC peering connection to Kafka. Flink accesses the private Kafka cluster through Confluent Cloud's internal routing, while the customer client reaches Flink through the AWS interface endpoint.
